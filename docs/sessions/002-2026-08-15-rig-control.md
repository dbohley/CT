# 002 — 2026-08-15 — rig control: CAN hardware layer and the four-state insertion procedure

## Goal

Build the physical rig's controller around the estimator: CAN transport for the
USB-CAN-FD RH02 adapter and CubeMars motors, a base axis and a needle axis, ToF and
tactile sensors, and the four-state insertion procedure (approach → estimate → insert →
advance) plus commanded withdraw and retract.

The constraint that shaped everything: almost none of the rig's physical constants are
known yet. So the goal was not "write the controller" but **write it so the unknowns are a
short, explicit, machine-checked list, and so every line of logic can be exercised end to
end in simulation before hardware exists.**

## Scope change

`CLAUDE.md` said this repo was the estimator only, and that the servo, the gating logic
and the safety monitor were "separate work — do not add them without being asked". This
session is that ask. All three arrive, plus hardware I/O, which the docs never
contemplated. The boundary section was rewritten deliberately rather than allowed to
erode, and the one-way dependency that remains (estimator never imports the rig) is now
enforced by a test rather than asserted in prose.

## What changed

**The estimator was not modified.** `identification/`, `tracking/`, `forecast.py`,
`layout.py` and `sources/` are untouched. `config.py` gained four optional top-level
sections (`rig`, `procedure`, `latency`, `servo`), all defaulting to `None`, so every
config and test predating this session still works. `registry.py` gained four tables
(buses, codecs, sensors, states) using the existing `_make_register`.

**Three new rules, each with a test**, mirroring the existing "layout.py owns state
ordering":

- `geometry.py` is the only place raw motor units become millimetres.
- Nothing in `control/`, `hw/` or `rt/` may import `plant/` — the hardware layer's
  equivalent of "no estimator code may read `truth`".
- The control tick never blocks on I/O; CAN receive runs on its own thread into a
  latest-frame-per-ID mailbox.

**The sim/real swap is two config fields**, `bus.backend` and the clock. There is
deliberately no separate simulated axis class: the simulated motors speak the *real*
CubeMars codecs over a loopback bus, so `CANAxis` — the same packing, parsing and limit
checks — runs identically in a unit test and on the bench. A byte-packing bug therefore
fails in simulation instead of waiting for a needle to be attached.

**`unknowns.py` is the headline deliverable.** 41 entries, each carrying the dotted config
key it plugs into, units, why it matters, how to measure it, an owner, a placeholder, and
which procedure states it blocks on hardware. It drives `ct-unknowns` (the table to hand
the team), `--check` against a config, and a hard gate: a run with a real bus backend
refuses to start while a placeholder blocks a state it intends to enter.

**The firing gate** is where `(s_hat, P)` finally gets consumed, and it is the paper's
methodological argument in code: fire only when the *forecast at t+h* lands at end-exhale,
**and** `sqrt(forecast_variance(h))` is under budget, **and** no increment has fired this
breath. An LMS predictor could answer the first; only the covariance answers the second.

## Decisions and rationale

**The base runs servo mode, the needle runs MIT mode.** Not arbitrary. MIT mode packs
position into 16 bits spanning ±12.5 rad by default — about two output-shaft turns, which
no realistic lead screw covers over the base's 200 mm of travel. Servo mode's int32 degrees
field does, and the base only ever needs point-to-point moves. The needle must *float*
(zero stiffness) during ADVANCE, and only MIT mode can express that. Both codecs are
implemented either way; this only sets the defaults, and if the real motors are flashed the
other way round that is a finding to act on, not to work around.

**`tau_cl` is computed, never configured.** `residual_lag()` evaluates
`-angle(T(j*omega_r)) / omega_r` from the compensated closed loop, so it genuinely varies
with breathing rate exactly as the settled decision requires. A configured constant would
have reintroduced the fixed `tau_a` that decision exists to reject.

**End-exhale is a fraction of the waveform's excursion, not an angle on `theta`.** A fixed
`theta` window means something different for every patient, because where the waveform
bottoms out depends on `phi_1` and every harmonic. The gate sweeps one cycle of the tracked
model, finds its real minimum and maximum, and asks whether the forecast sits in the bottom
`exhale_band_frac`. Waveform-relative, so it means the same thing for any breathing shape.

**Depth is measured against the end-exhale skin position, not the instantaneous one.**
Measured instantaneously it swings by the entire breathing excursion whenever the needle
holds position, and the termination test would fire on whichever tick caught a peak. The
end-exhale datum is stable and is the same reference every increment was commanded against.

**`SimClock` is the load-bearing decision for testability.** A twenty-minute procedure runs
in a couple of seconds, deterministically, with no hardware, executing the identical
control code. `test_boundaries.py` forbids any direct `time.monotonic()` in `control/` or
`rt/`, because one such call would silently break every procedure test.

## Findings

- **MIT mode's position range is a real constraint, not a detail.** ±12.5 rad is roughly
  two turns. Exceeding it does not error — the command *saturates silently*, the axis
  stops short, and feedback agrees with the clipped value. Cost an hour before `CANAxis`
  was made to refuse construction when `travel_mm × counts_per_mm` does not fit.
- **"Hold position" must re-issue the last command, not re-read the encoder.** Re-reading
  every tick cancelled each creep increment partway through its move, and would let a
  backdrivable axis be pushed anywhere at all, since each tick ratchets the target to
  wherever it was just shoved.
- **Steady-state error under impedance control is `load / kp`.** At `kp = 80` the needle
  stalled 4 mm short of a 10 mm command with the motor at full effort. This is a real
  design constraint on the needle drive: `kp` must be high enough that the residual error
  fits inside the placement tolerance, and the arrival test needs a stall detector because
  a tight tolerance the physics forbids just becomes a timeout.
- **The tactile sensor's usable stroke must exceed the full breathing excursion.** If it
  does not, there is no seating depth at which the whole waveform is visible — the trough
  clips at one end or the peak at the other — and APPROACH cannot succeed at any tuning.
  A hardware sizing requirement worth knowing before anyone orders a sensor.
- **The residual monitor earned its place immediately.** It caught the tracker being
  seeded on the identifier's rebased clock while being fed loop-monotonic timestamps — a
  49 s jump on its first step, which showed up as NIS 218 against an expected ~1.
- **Tissue must be modelled as bounded friction, not a spring.** An unbounded grip makes
  insertion impossible (the needle stalled 1.5 mm in); too much viscous damping relative
  to the slip limit makes the tissue let go every tick, so the needle never rides and the
  telemetry looks exactly like a controller that forgot to float.
- **A position axis is type-1.** Modelling the needle as a plain second-order lag gave a
  closed loop that tracked only 55% of its reference and *led* rather than lagged, which
  silently clamped `tau_cl` to zero and dropped a term out of the horizon.

## Open questions

Carried into `CLAUDE.md`. New or changed this session:

- **Which firmware are the CubeMars motors actually flashed with?** ADVANCE needs MIT-mode
  float on the needle. Recommendation: needle in MIT mode, base in servo mode.
- **What interface/channel does the RH02 enumerate as?** `python -m can.detect_available_configs`
  with the adapter attached settles it. Nothing else can be tried on hardware until it is.
- **Sim fidelity of the float/ride behaviour is not fully verified.** The needle is
  commanded to float correctly and the CAN frames are right; how faithfully the simulated
  tissue carries it through a breath was not run to ground, and the tuning is a placeholder
  until there is a real phantom to measure. This affects the simulation's realism only, not
  the controller.
- Everything in `docs/unknowns.md` — 34 of 41 entries still at placeholders.

Unchanged and still open from session 001: sensor modality and real latency, target organ
and amplitude, clinical tolerance, insertion depth and needle velocity, real sensor data
availability, Singh et al. 2020 confirmation.

## Next steps

1. **Settle the CAN link.** `can.detect_available_configs`, then `can.viewer`, then node
   IDs and frame layouts. Everything else on hardware is blocked behind it.
2. **`ct-rig --config rig_bench --dry-run`.** Exercises bus, codecs, geometry and the full
   state machine with every motor command suppressed. Run before anything moves.
3. **Measure the mech block** — `counts_per_mm` for both axes, the three offsets, the
   direction signs, the travel limits. `ct-unknowns --format md` has the procedure for
   each. These unblock APPROACH.
4. **Calibrate `tactile_counts_to_mm` against a micrometer stage**, keeping the residuals.
   If it is not linear, the config has to grow from a scalar to a curve. Everything
   downstream is scaled by this one number.
5. **Identify the needle plant** from a step response and re-derive the lead against it,
   rather than hand-tuning. `tau_cl` and therefore `h` follow from it.
6. **Turn on the breath hold** (`procedure.approach.breath_hold_s`, already 15 s in
   `rig_bench.yaml`) and check whether `R` from it beats the residual-variance fallback —
   the failure mode session 001 quantified at NIS 0.027.
7. **Calibrate `forecast_variance` against realised error** before trusting the gate's
   `max_forecast_std_mm`. Still the outstanding item from session 001's next steps.
