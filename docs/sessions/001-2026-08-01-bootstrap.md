# 001 — 2026-08-01 — bootstrap

## Goal

Stand up the project from an empty repo: a working end-to-end FFT-identification +
EKF-tracking pipeline for respiratory motion, structured so the signal source,
identification method and tracking method are each replaceable without touching the other
two. Plus the conda environment, the runnable experiment scripts, and the documentation
conventions to build on.

Scope was the full vertical slice, not a skeleton — all three synthetic generators, the
identifier, the EKF, forecasting, diagnostics, CLI and tests, so real experiments could run
the same day.

## What changed

Everything; the repo previously held a two-line README.

**The estimator.** Two stages behind three `typing.Protocol` boundaries, resolved by name
through a registry so a config string selects an implementation. Stage 1 estimates a coarse
`omega_r` (FFT peak with parabolic interpolation, cross-checked against autocorrelation),
runs an OLS harmonic regression at that fixed frequency, picks `K` by the 95% energy rule,
and derives `P0` from the OLS covariance via a delta-method Jacobian, `R` from a breath-hold
segment or the residual variance, and per-state `Q` from breath-to-breath refits. Stage 2 is
an EKF with analytic Jacobians, a scalar-measurement gain (a division, not a solve) and a
Joseph-form covariance update.

**Forecasting** is a pure time-advance, `theta -> theta + omega_r*h`. The known-wrong
alternative — rotating every harmonic by one common angle — is implemented as
`naive_common_phase_forecast` purely so a test can assert it is wrong.

**Data generators**: multi-harmonic sinusoid (with an optional frequency ramp), Lujan
`cos^{2n}`, the Singh et al. 2020 RC-piecewise chest-wall model, and a CSV reader that is
the seam for real sensor data.

**Six CLI scripts** over a YAML-config layer with dotted-key CLI overrides, plus six
diagnostic figure types.

Roughly 4,900 lines across `src/` and `tests/`; 152 tests.

## Decisions and rationale

**`typing.Protocol` over ABCs.** A replacement tracker needs matching methods and nothing
else — no inheritance, no import of a base class. That is what makes "swap in a UKF later"
a real claim rather than an aspiration. Proven by two tests that register a dummy tracker
and a dummy identifier and run the whole pipeline through them.

**`StateLayout` as a hard rule.** Protocol boundaries make interfaces swappable, but every
stage still has to agree that slot 5 means `phi_2`. A disagreement raises nothing — the
numbers just go quietly wrong. So indices live in exactly one place, and a test asserts the
index sets form an exact permutation of `range(n)` for every `K`.

**`Q` measured, not tuned.** The persistence model is a convenient lie; `Q` is where it is
paid for. Per-breath refits give the amplitude/phase spread directly. Frequency is handled
separately, over overlapping four-breath windows, because one breath does not resolve
`omega` well enough for its scatter to mean anything.

**Analytic Jacobians only at runtime**, with finite differencing confined to
`tests/test_jacobians.py`. At sensor rate, numeric differencing costs `K+3` extra
evaluations per step for a worse derivative.

**Constraints off by default.** Amplitude sign-folding and `omega` bounds are implemented
but disabled, so the raw filter behaviour is observable. A filter that needs clamping to
stay sane is saying something about `Q`, and that should be visible.

**Configs reflect measurements, not aspirations.** `rc_piecewise.yaml` keeps the settled 95%
threshold even though it under-fits, with the measured numbers in the file header, and
`rc_piecewise_k4.yaml` sits beside it as the threshold that actually works. Tuning the
default to hide the finding would have buried the most useful thing this session learned.

## Findings

**1. The 95% energy rule is waveform-dependent, and the RC model is where it breaks.**
This was the open question the reference doc flagged. The answer is subtler than "the kink
pushes K higher": at 95% the rule picks `K=1` for the RC model, because the energy really
is concentrated in the fundamental (97.7%). But the residual is visibly periodic, not white,
and tracking suffers.

| threshold | K | tracking RMSE |
|---|---|---|
| 0.95 | 1 | 0.439 |
| 0.99 | 2 | 0.289 |
| 0.999 | 4 | 0.108 |

Against `noise_std = 0.15`, the 95% rule tracks three times *worse* than the noise, while
99.9% tracks below it. The mechanism is that Lujan's Fourier series terminates exactly at
`k=n` (harmonic `n+1` is numerically zero), whereas the RC model's coefficients decay but
never reach zero — cumulative energy is still climbing at `k=6` (0.99971). Ljung-Box rejects
whiteness at every `K` tried, which is the tell that no truncation fully captures it.

Practical consequence: the threshold must be re-validated on real data, and Ljung-Box on
the innovations is the diagnostic to validate it *with* — NIS alone does not catch this,
because `R` from the residual fallback silently absorbs the mismatch.

**2. The residual-variance fallback for `R` fails in a specific, predictable way.** With a
drifting fundamental, Stage 1 fits a whole 90 s window at one fixed `omega`, so the residual
contains the frequency mismatch as well as the sensor noise. `R` came out at 0.806 against a
true noise variance of 0.0225 — a factor of 36. The filter then over-trusts its model and
NIS collapses to 0.027 against an expected 1.0.

This is exactly why the reference doc calls the residual an upper bound only, but it is
worth having the number: it is not a small effect. A breath-hold segment is implemented and
tested (`identifier.params.breath_hold_window`) and should be collected with the real data.

**3. Two errors in the reference doc's RC-piecewise formulas.** Found by substituting the
stated solution back into `V' + V/tau_rs = P/R_rs`:

- `A2 = a2 - 2*a2*tau_rs` should be `A2 = a1 - 2*a2*tau_rs` — the linear pressure
  coefficient must appear, and `A3` in the same block already uses `a1` consistently.
- The exhale term `e^{+(t-t1)/tau}` should be `e^{-(t-t1)/tau}` — a growing exponential
  would make exhalation diverge.

Both are corrected in the generator, documented at the point of use, and pinned by
`test_rc_inhale_coefficients_solve_the_ode`, which checks the coefficients against the ODE
directly rather than against a transcription. The archived reference doc carries a note.

**4. A metric defect, found and fixed during verification.** Forecasts reaching past the end
of a finite recording were being scored against `np.interp`'s clamp-to-endpoint value,
inflating the reported forecast RMSE by 3.6x on the CSV path (0.0222 vs a true 0.0061). The
truth function now returns NaN outside the record and `forecast_errors` drops those samples,
reporting `n_unscored` so the shrinking sample size stays visible. This only affected CSV
sources; synthetic generators can be evaluated exactly at `t+h`.

**5. `lujan_n3` under-tracks at `K=2` (RMSE 0.222 vs noise 0.150).** The 95% rule is
behaving as documented here — the third harmonic really does carry under 0.4% of the
energy — but "negligible energy" and "negligible tracking error" are not the same claim.
Worth revisiting alongside finding 1.

## Open questions

Unchanged from the reference doc, all still unresolved and now mirrored in `CLAUDE.md`:
sensor modality and measured latency; target organ and motion amplitude; clinical tolerance
epsilon; insertion depth / needle velocity (sets `T_ins`); breath-hold viability; real data
format, rate and timeline; confirmation that the team's intended chest-wall model is Singh
et al. 2020.

One new question, raised by finding 1: **what energy threshold should the K rule actually
use?** 95% is right for Lujan and wrong for the RC model. Candidate replacements worth
testing once real data exists — a whiteness-based stopping rule (increase `K` until
Ljung-Box stops rejecting) rather than a fixed energy fraction.

Note also that a breath-hold segment would resolve two open items at once: it is both the
proposed clinical fallback and the preferred source of `R`.

## Next steps

1. **Decide the `K` criterion.** Prototype a whiteness-based stopping rule alongside the
   energy rule and compare on all three synthetic models. This is the highest-value open
   item, and finding 1 shows the current rule is not safe to assume on real data.
2. **Check `lujan_n3` under-tracking** (finding 5) — probably the same issue as 1, but
   confirm rather than assume.
3. **Add a breath-hold segment to the synthetic generators** so the preferred `R` path is
   exercised end-to-end by a config, not only by a unit test.
4. **Real-data intake.** When teammates deliver a recording, `CSVSource` is the entry point.
   Expect to need resampling (it currently rejects non-uniform timestamps) and a decision
   about what `y_clean`-free validation looks like.
5. **Forecast covariance.** `forecast_variance` exists and is tested for monotonicity but is
   not yet calibrated against realised error. That is the signal the gate will threshold on,
